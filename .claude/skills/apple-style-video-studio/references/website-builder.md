# Создание сайтов

Сайт — такой же результат студии, как видео: тот же бриф, те же токены дизайна, те же иконки, те же языки. Поэтому сайт собирают из `brief.json` и `i18n`, а не с нуля.

## Выбор формата
- **Лендинг / визитка / промо к видео** → `assets/site-template/index.html` (один файл, без зависимостей, открывается двойным кликом). Выбирай по умолчанию.
- **Многостраничный сайт, блог, магазин, веб-приложение** → Vite + TypeScript (или Astro для контентных сайтов), компоненты, тот же дизайн-токены в CSS-переменных. Тексты — файлы `i18n/<lang>.json`, маршруты `/<lang>/...`.
Спроси пользователя только о том, что нельзя вывести: хостинг, нужна ли форма/оплата/админка. Остальное реши сам и скажи что выбрал.

## Процесс
1. **Бриф.** Если есть старый сайт — проанализируй (этап 1 основного пайплайна). Если нет — составь бриф из ответов пользователя: что за продукт, для кого, главное действие (CTA).
2. **Структура.** Один сайт — одно главное действие. Типовой лендинг: Hero → 3 ключевые возможности → видео/демо → доказательство (цифры, цитаты — только реальные) → CTA → футер. Не добавляй секции «для объёма».
3. **Дизайн-токены.** Перенеси палитру, шрифты, радиусы из `brief.json` в `:root`. Светлая и тёмная тема через `prefers-color-scheme`. Правила стиля — `apple-style.md` (воздух, один акцент, крупная типографика, сдержанное движение).
4. **Контент.** Все тексты в таблице I18N (или JSON) и подставляются через `textContent`. Не вставляй пользовательские/внешние строки через `innerHTML`.
5. **Иконки и картинки.** Свой SVG-набор (`stroke=currentColor`); картинки в `webp/avif` + запасной `jpg`, `width/height` заданы, `loading="lazy"` ниже первого экрана, `alt` на каждом языке. Видео из этапа 4 вставляй как `<video controls playsinline preload="metadata">` с субтитрами `<track>`.
6. **Языки.** Автоопределение + переключатель, `lang`/`dir` на `<html>`, RTL через логические свойства CSS (`margin-inline-start`, `inset-inline-*`), `hreflang` для многостраничных, шрифты с нужными глифами. Длинные немецкий/русский не должны ломать вёрстку.
7. **Сборка и проверка.** Открой в Playwright, сними скриншоты на 390, 768, 1440 px, в светлой и тёмной теме и на RTL-языке; смотри консоль на ошибки.

## Безопасность (аудит сайта, этап 5)
- CSP `default-src 'self'` (см. шаблон), без внешних скриптов/шрифтов/трекеров, если пользователь явно не просит. Если нужны — фиксируй версию и добавляй `integrity`.
- Нет `eval`, `document.write`, `innerHTML` с данными; ссылки `target=_blank` с `rel="noopener noreferrer"`.
- Формы: валидация на клиенте и сервере, CSRF-токен, лимит запросов, никаких секретов в клиентском коде и в репозитории. Для почты/оплаты используй сервер или провайдера, ключи — в переменных окружения.
- Заголовки на хостинге: `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`, `frame-ancestors 'none'` (через CSP или `X-Frame-Options`).
- Зависимости: `npm audit`, без неиспользуемых пакетов, lockfile в репозитории.
- Приватность: без аналитики до согласия, если она нужна; не собирай лишних данных; ссылки на политику конфиденциальности, если есть формы.
- Не копируй чужой код/картинки/шрифты без лицензии; проверь лицензии шрифтов.

## Качество (аудит)
- Lighthouse (Playwright/Chromium): Performance ≥ 90, Accessibility ≥ 95, Best Practices ≥ 95, SEO ≥ 95.
- LCP ≤ 2.5 с, CLS ≤ 0.1; первый экран без блокирующих ресурсов; вес страницы без видео ≤ 500 КБ.
- Семантика: один `h1`, иерархия заголовков, `main/header/nav/footer`, skip-ссылка, фокус виден, управление с клавиатуры, `prefers-reduced-motion`.
- Мета: `title`, `description`, Open Graph (картинка 1200×630), `favicon`, `canonical`, `sitemap.xml`/`robots.txt` для публичных сайтов.
- Адаптив без горизонтального скролла от 320 px; цели нажатия ≥ 44 px.
- Выдача на «живость»: нет шаблонного «ИИ-вида» — никаких фиолетово-синих градиентов, случайных эмодзи в заголовках, одинаковых карточек-сеток без смысла, стоковых лиц.

## Выдача
Папка `site/` (index.html или собранный `dist/`), `qa-report.md` с результатами аудита и zip. Для просмотра в интерфейсе опубликуй страницу как артефакт. Если нужен хостинг — предложи GitHub Pages / Netlify / Cloudflare Pages и подготовь файлы, но не публикуй наружу без согласия пользователя.
